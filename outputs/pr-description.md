# PR: TCPA Regulatory Compliance API — Phase 1 Initial Delivery

## Summary

This PR delivers the TCPA Regulatory Compliance API (Phase 1), a centralized
SMS compliance middleware that enforces TCPA Section 64.1200 opt-out rules
across all Southern Company Gas applications. Every outbound SMS from BizTalk,
GCMA, KMI Active, and ARM/Construction Portal is now gated through this API
before reaching Cool Text/Twilio; any customer who sends an opt-out keyword
(STOP, QUIT, END, REVOKE, OPT-OUT, CANCEL, UNSUBSCRIBE) is immediately blocked
across all SCG applications and receives a confirmation within 60 seconds. This
is a mandatory regulatory compliance system — it must be live and enforcing by
January 31, 2027.

## Why These Changes

Southern Company Gas is legally required to comply with TCPA Section 64.1200
by January 31, 2027. Five SCG applications (BizTalk, GCMA, KMI Active,
ARM/Construction Portal, CCB/My Account) currently send SMS to customers
without any centralized opt-out enforcement. An opted-out customer can still
receive messages from any of these applications because there is no shared
opt-out registry. This API closes that gap.

The business goals this delivery satisfies (from `outputs/requirements.md`):
- **GOAL-1:** Zero SMS messages delivered to opted-out cell numbers via the TCPA API.
- **GOAL-2:** 100% of in-scope application messages routed through TCPA API.
- **GOAL-3:** Audit log retained 5 years; weekly compliance reports with zero manual intervention.
- **GOAL-4:** Opt-out acknowledgement ≤ 60 seconds; opt-out effective within 10 days.

### Known Test Gaps

1. **No integration tests:** Full HTTP pipeline tests (real JWT middleware, real EF Core InMemory) were not written. Controller auth (401/403) is asserted via Moq-simulated user context, not real JWT validation middleware.

2. **Cache TTL expiry not tested (STORY-001 AC-004):** Requires a `TimeProvider` abstraction to be injected into `ApplicationRegistryService`. Currently uses `IMemoryCache` directly with wall-clock TTL.

3. **Debug logging toggle not tested (STORY-020):** Dynamic App Configuration polling cannot be unit-tested without a running App Configuration endpoint.

4. **Always Encrypted and TLS enforcement (STORY-022):** Verified by schema review and architecture ADR-003. No automated test can validate column-level encryption without a real Azure SQL instance with CMK/CEK provisioned.

5. **ManualReportTriggerFunction end-to-end:** Authorization enforcement on the Azure Functions HTTP trigger requires a running Functions host to verify.

6. **`WriteOptOutEventAsync`/`WriteBlockedOutboundEventAsync` convenience methods:** Tests use loose-mode Moq; dedicated assertions for `RecordId = Guid.NewGuid()` were not present before CR-005 was fixed in-session.

## Architecture & Design Notes

1. **Fire-and-forget scope isolation (CR-004 resolution):** The inbound SMS controller returns 200 OK immediately to Cool Text (preventing timeout retries) and dispatches opt-out processing to a background `Task.Run` with a fresh `IServiceScopeFactory`-created DI scope. The correlation ID is captured from the request scope and injected into the new scope's `CorrelationIdAccessor` before processing begins. This ensures all audit log entries from the background processing carry the correct correlation ID linking them to the originating webhook call.

2. **AuditLog immutability — dual enforcement:** Database-level DDL trigger (`trg_AuditLogEntries_Immutability` in `002_AuditLogImmutabilityTrigger.sql`) rejects all UPDATE/DELETE statements. Application-level enforcement via `IAuditLogService` interface which exposes no Update/Delete methods. Neither layer alone is sufficient for regulatory compliance; both are required.

3. **Always Encrypted — not yet applied:** The EF Core migration creates `CellPhoneNumber` as a plain `nvarchar(20)` column. Always Encrypted (CMK + CEK provisioning in Azure Key Vault) is a post-migration infrastructure step (TASK-061) that requires the platform team. The `Column Encryption Setting=Enabled` connection string parameter is set but will not encrypt data until the platform-side key provisioning is complete. **Do not promote to production until TASK-061 is confirmed complete.**

4. **CCB/My Account inactive by default:** CCB is seeded with `IsActive = false`. The compliance gate treats CCB messages identically to unregistered applications (no enforcement, no audit entry). Activating CCB requires completing the CCB TCPA Activation Gate checklist (end-to-end integration test, Legal sign-off, production smoke test) and a configuration-only deployment to set `IsActive = 1`. See `docs/ccb-activation-gate.md` (TASK-052 deliverable).

5. **`AuditEventType` enum reconciliation required before first build:** `ReportingService.QueryOptedOutAsync` references `AuditEventType.SmsBlocked`; the enum definition in `Domain/AuditEventType.cs` uses `AuditEventType.BlockedOutbound`. **This will not compile.** Change `SmsBlocked` reference in `ReportingService` to `BlockedOutbound` before the first build.

6. **`DomainModels.cs` stub must be deleted:** An earlier agent created `src/TCPA.Api/Domain/DomainModels.cs` as compile-time stubs. The Foundation agent has delivered the authoritative domain model files. The stub file creates naming conflicts. **Delete `src/TCPA.Api/Domain/DomainModels.cs` before the first build.**

7. **Seed script requires placeholder substitution:** `001_ApplicationRegistrationSeed.sql` contains `[PLACEHOLDER: ...]` values for all five Cool Text account IDs and callback URLs. These must be replaced with production values from Azure Key Vault before the seed script is run in any environment. The script will fail with constraint violations if placeholders are not replaced.

8. **Opt-out confirmation SMS text — Legal approval pending:** The confirmation message text is loaded from `TCPA:OptOutConfirmationSmsText` in Azure Key Vault at dispatch time (not hardcoded). The key must contain the legally-approved text before go-live. A missing or empty key will cause `ConfirmationDispatcher` to log a critical error and skip sending the confirmation, which is a TCPA violation.
