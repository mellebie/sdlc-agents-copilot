# PR: TCPA Regulatory Compliance API — Phase 1 Delivery

## Summary

This PR delivers the complete Phase 1 implementation of the TCPA Regulatory Compliance API — a centralized SMS opt-out enforcement service for Southern Company Gas. It intercepts all outbound text messages from four in-scope Gas applications (BizTalk, GCMA, KMI, ARM), enforces STOP keyword opt-out decisions globally across all four LDCs, suppresses outbound messages to opted-out numbers at two checkpoints, and generates weekly compliance reports. The system must be live before the federal TCPA mandate effective January 31, 2027.

## Why These Changes

Southern Company Gas is subject to the federal Telephone Consumer Protection Act (TCPA), which requires that any customer who sends a STOP message to a registered SMS number be immediately opted out and never receive further messages from any application sharing that platform. The January 31, 2027 enforcement date is fixed and non-negotiable.

Today, each Gas application (BizTalk, GCMA, KMI, ARM) manages opt-out in isolation. A customer who sends STOP via one application channel can still receive messages from the others. This creates TCPA §227 liability exposure across all four LDCs. The TCPA Compliance API closes this gap by acting as the single broker for all inbound and outbound SMS — every message passes through the compliance gateway, opt-out status is enforced globally, and every compliance event is immutably audited.

## Architecture & Design Notes

The system uses an event-driven architecture with three independently deployable .NET 8 worker services backed by a shared library:

- **TCPA.Api** — synchronous API gateway; acknowledges requests quickly via Kafka publish; never blocks on downstream processing
- **TCPA.MessageProcessor** — async Kafka consumer for `inbound-messages`; processes opt-outs, sends confirmations, routes general replies
- **TCPA.OutboundDispatcher** — async Kafka consumer for `outbound-messages`; applies two compliance gates before dispatching to Cool Text/Twilio
- **TCPA.Core** — shared library; owns the data model, EF Core migrations, repositories, and core compliance services

Key decisions:
- **Fail-closed throughout:** If the opt-out status store is unavailable at any decision point, the system returns 503 or suppresses the message — never guesses or allows an unchecked send (SPEC-007 BR-027).
- **Dual-gate suppression:** Queue-time check provides immediate feedback to the caller; send-time check guards against race conditions where a STOP arrived after the queue-time decision was already made.
- **Composite PK on ProcessedMessages `(MessageId, Endpoint)`:** Supports per-endpoint idempotency — the same message ID can be processed once by each distinct Kafka consumer group without collision.
- **Phone number hashing boundary:** Raw E.164 stored in database columns (`AuditLog.PhoneNumber`, `OptOutStatus.PhoneNumber`). HMAC-SHA256 hash used exclusively in Serilog log parameters and `AuditLog.Details` JSON.
- **Scope-per-Kafka-message:** `IServiceScopeFactory.CreateAsyncScope()` inside the message processing loop — fresh `TcpaDbContext` per message prevents stale change-tracker state across retries.

Reference `outputs/architecture.md` and `outputs/docs/architecture.md` for the full ADR set.
